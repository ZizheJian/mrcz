论文定位
========

- 论文对象称为high-order finite/spectral-element field data；仅讨论NekRS/Nek5000时使用
  hexahedral spectral-element field data，不再把HOHS当作已有公认术语。
- DCC论文只把MRCZ作为主算法。自写SZ3-3D-GLL不作为第二个主要贡献；必要时只作为简短的
  GLL-aware interpolation内部对照。点云压缩属于另一项工作。
- 当前正式MRCZ流程为：逐element张量积基变换、系数量化、反变换、逐点残差量化、
  coefficient-major转置、Huffman和Zstd；partition之间OpenMP并行。
- 当前默认coeff_eb_scale=0.05，正式方法只启用coefficient transpose。此前zero-frequency
  expanding和zero-map均已备份到c_codes/trash并因无稳定收益而删除。

第一阶段：冻结正确且可复现的MRCZ
=================================

[ ] 1. 清理正式方法与诊断入口的边界。
       - 保留MRCZ-3D-GLL作为唯一正式MRCZ压缩格式；
       - MRCZ-3D-GLL-experimental当前实际上执行角点/中心点预测诊断且不写bitstream，名称容易误导；
         将其改成明确的诊断工具或归档到experiments，不再暴露为可解压方法；
       - 不在本阶段删除仍用于历史复现实验的SZ3代码。

[ ] 2. 审计并版本化MRCZ bitstream metadata。
       逐项确认解压所需的word size、element shape、transform、grid assumption、coeff_eb_scale、
       coefficient transpose、partition边界、field信息和error-bound信息是否已写入文件。
       当前解压依赖但bitstream没有保存的选项必须写入版本化header，不能依赖调用者使用默认值。
       增加未知版本、截断文件、错误method和错误数据类型的失败测试。

[ ] 3. 建立正式小数据回归矩阵。
       - test0：6*6*6 float；mixlay0：8*8*1 float；tc_channel0：8*8*8 double；
       - 覆盖REL=1e-2、1e-4、1e-6、1e-8和必要的ABS测试；
       - 每次检查最大误差、PSNR、重建数量、压缩后文件边界和编解码一致性；
       - 对float提升为double的路径单独验证；
       - REL=1e-15时现有标量和AVX2路径都可能达到约1.63倍EB。根据数据尺度和机器epsilon建立
         可解释的最小可保证EB检查：无法严格保证时应拒绝或明确警告，不能静默宣称error-bounded。

[ ] 4. 实现值域不超过2*abs_eb的常数field编码。
       复用或版本化constant flag，保证float/double、正负值、零值和恰好位于阈值处均可对称解压。

第二阶段：只研究可能增强MRCZ论文贡献的算法
==========================================

[ ] 5. 系统确定全局coeff_eb_scale。
       在五个NekRS数据的多个field和目标PSNR上扫描scale，分别统计coefficient QB、residual QB、
       Huffman metadata和最终Zstd payload的bits/value，以及变换、量化、Huffman和Zstd时间。
       先确认0.05是否接近稳定最优，再决定默认值；比较必须基于相同实际PSNR而不是相同输入REL。

[ ] 6. 研究按变换模式分组的coefficient error bound。
       - 根据逆变换基函数的误差放大和模式阶数设计少量固定分组，不给每个系数单独保存参数；
       - 候选分组必须由编解码双方从element shape确定，或只增加极少metadata；
       - 与最佳全局scale比较同PSNR BR、最大误差、速度和metadata；
       - 只有在多个数据上稳定改善并能清楚解释时才纳入MRCZ，否则停止。

[ ] 7. 分析MRCZ无损阶段，而不是继续泛化SZ3的多tree实验。
       报告coefficient transpose开关前后的BR和时间，并按变换模式统计零比例与符号分布。
       只有这些统计显示不同模式确实需要不同码表时，才尝试少量固定coefficient group/tree；
       必须把每棵tree的metadata和Zstd后的最终大小计入结果。

第三阶段：建立可信的正式baseline
==============================

[ ] 8. 使用官方压缩器API测试自然tensorization。
       对官方SZ3至少测试1D展平、2D [E,N^3]、3D [E*N0,N1,N2]、逐element 3D和
       4D [E,N0,N1,N2]；所有布局使用相同API、error-bound模式和完整bitstream大小。
       结果可给出SZ3-best-layout oracle包络线，但oracle不作为可部署方法。

[ ] 9. 冻结论文baseline集合和统一接口。
       候选为官方SZ3布局、QoZ-4D-uniform、ZFP-4D-uniform、SPERR-3D-uniform及必要的SZ2历史结果。
       为每种方法记录输入维度、坐标假设、partition方式、bitstream拼接、float/double支持、
       error-bound语义和计时范围。自写SZ3/QoZ预测器不进入主要结果，除非只作为内部诊断。

第四阶段：DCC正式实验
===================

[ ] 10. 冻结数据、field和质量范围。
        使用五个NekRS数据及其所有非常数物理field；小数据用于回归，大数据pb0和jicf0用于主要结果。
        输入使用一组REL EB生成曲线，但所有压缩效果都按实际PSNR比较。明确说明坐标、header、
        element map和尾metadata是否计入bitstream大小。

[ ] 11. 生成rate-distortion结果。
        对MRCZ和全部正式baseline生成BR-PSNR曲线；同时报告最大误差/EB、压缩率和异常点。
        t1为每个data/field生成独立的rate-distortion CSV，测试结束自动清理压缩及解压临时文件。

[ ] 12. 生成速度和扩展性结果。
        - 在多个代表PSNR点报告压缩/解压单核throughput，而不是只选择一个宽松EB；
        - 在pb0和jicf0上测试1、2、4、8、16、32、64、128线程strong scaling；
        - throughput使用程序内部backend时间并以调和平均汇总field；
        - 单独报告变换+量化、Huffman和Zstd时间，解释扩展瓶颈。

[ ] 13. 完成MRCZ消融。
        最少包含coefficient transpose关闭/开启、不同全局coeff_eb_scale，以及第6或第7项最终被采纳的
        优化。每项同时报告同PSNR BR、压缩/解压throughput、metadata和最大误差。

[ ] 14. 验证格式与软件覆盖范围。
        NekRS是论文主要格式；MFEM和Nektar++只选小样例做功能性编解码验证，不用小样例的压缩率
        支撑主要结论。确认安装后的header-only mrcz::mrcz target和两个命令行程序均可复现结果。
