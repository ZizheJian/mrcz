MRCZ C++代码整理待办事项
========================

目标
----
在继续使用.hpp + .tpp（header-only）的前提下，把mrcz_core整理成职责清楚、可以被
其他C++程序直接调用的库。命令行程序只负责解析参数；MRCZ核心流程通过param_class
调用。外部程序仍然可以自由读取和修改param_class的public成员。

处理原则
--------
- 一次只做一个小步骤，每一步都重新编译mrcz_compress和mrcz_decompress。
- 尽量不同时进行目录移动、接口修改和压缩格式修改。
- 修改压缩bitstream格式时，必须同时修改解压端并考虑旧文件兼容性。
- regular/irregular表示element三个离散维度是否相等，不表示物理几何是否规则。


近期已完成的修复
================

[x] 修复变换矩阵语义调整后，压缩和解压调用没有同步更新的问题。
    当前定义为：
    - neg_L：反变换矩阵，即基函数在采样点上的取值组成的矩阵；
    - L：正变换矩阵，即inverse(neg_L)。
    因此forward_transform_regular/irregular使用L，
    inverse_transform_regular/irregular使用neg_L。

    问题出现时，程序把neg_L用于正变换、L用于反变换。两者仍互逆，所以解压结果
    没有明显错误，但产生的系数不再具有正常的低频集中和高频趋零特征，导致系数流
    异常大，并且最终误差只使用了很小一部分error bound。

    使用mixlay0.f00001的P字段、单CPU、abs_eb约为1e-3验证：
    - 旧版9e89273：BR=0.929063；
    - 错误版本：BR=13.020156，max_err约为error bound的2.96%；
    - 修复后：BR=0.929141，max_err约为error bound的99.61%。
    修复后重新运行了t1，MRCZ的rate-distortion结果已恢复，其他baseline结果不变。
    用于对比的9e89273临时副本曾放在/tmp/mrcz-old-WG8Yak；完成回归后已删除。
    /tmp是节点本地短期空间，可能因空间不足或节点重启被清理，不作为后续工作的
    持久副本。需要再次对比时直接从Git提交9e89273重新导出。

[x] 统一不同压缩器共用的header和element map文件名。
    这两类数据只取决于原始文件，与具体压缩器无关。现在统一使用：
    - <data_path>_header.mrcz；
    - <data_path>_element_map.mrcz。
    各压缩器不再分别生成_header.<method>和_element_map.<method>副本；field压缩文件
    和解压结果仍保留method后缀以区分压缩器。

第二阶段：提供完整的header-only调用入口

[x] 5. 在mrcz_core中增加完整压缩入口，例如：

           mrcz::compress(param_class<T> &params);

       压缩只保留这一种执行入口，不再增加compress(argc,argv)重载。
       外部用户可以自己创建并修改param_class，也可以调用独立的
       parse_compress_args(argc,argv)得到params，最后都调用mrcz::compress(params)。
       mrcz::compress是位于mrcz_core之外的顶层分派入口：根据method调用
       mrcz::core::compress或mrcz::baseline::compress，但不让mrcz_core依赖baseline。
       mrcz_core应支持项目自身的mrcz和sz3-hohs两种方法；sz2-0、sz2-1、sz3-1、
       zfp和sperr属于baseline，不应成为mrcz_core的内部依赖。
       该入口应负责目前compress.cpp中compress1/compress2包含的MRCZ公共流程：
       - 检查和初始化params；
       - 读取header；
       - 保存header和element map；
       - 确定CPU数量并建立partitions；
       - 逐field读取数据；
       - 计算field动态范围及绝对/相对误差界；
       - 根据原始类型和所需精度选择float或double；
       - 调用正确的MRCZ压缩实现并写出结果。
       当前进度：已增加mrcz_core/mrcz.hpp和compress.tpp，并建立只执行一次的
       compress_file_with_backend。MRCZ和所有baseline已共用参数检查、header读取、partition创建、
       field读取、动态范围计算、float/double选择和bitstream写出流程。已删除
       compress.cpp中重复的compress1/compress2。sz3-hohs已移入mrcz_core，并通过
       mrcz::core::compress入口调用；sz3-1 baseline仍可复用其预测实现。顶层
       mrcz::compress已统一分派core和baseline。
       已完成独立于CLI的编译测试：外部源文件创建param_class<float>、自由设置format、
       data_path、error bound、method和max_cpus，并成功实例化
       mrcz::core::compress(params)。t1也已通过顶层mrcz::compress(params)完成运行时回归。

[x] 7. 让compress.cpp和decompress.cpp只保留CLI逻辑。

第三阶段：分离正式压缩与实验压缩
=================================

[x] 9. 先为regular/irregular改一个不容易误解的名字，或至少补充明确注释。
       当前含义：
       - regular：element_shape为(n,n,n)，使用等尺寸快速变换内核；
       - irregular：element_shape为(n0,n1,n2)，使用通用尺寸变换内核。
       它们与element的物理扭曲或退化无关。
       微基准显示，在8x8x8 element上两套正/反变换内核的性能差异不到1%，regular
       没有可测量的优势。因此不再重命名两套路径，而是决定删除regular专用内核，
       统一使用支持(n0,n1,n2)的general-dimension内核。

[x] 10. 合并regular和irregular重复的外围流程。
        微基准和小数据回归均未显示equal-dimension内核具有实际优势，因此不再保留
        两套变换内核。现在所有MRCZ数据统一调用支持任意(n0,n1,n2)尺寸的
        forward_transform/inverse_transform，并只保留一套compress_mrcz/decompress_mrcz
        外围流程。原compress_regular、compress_irregular、decompress_regular和
        decompress_irregular文件均已删除。

[x] 11. 建立不含实验功能的正式mrcz方法。
        method=mrcz使用普通均匀量化区间，并完整编码所有系数模式。

[x] 12. 评估mrcz-experimental中的两项实验优化。
        mrcz-experimental复用compress_mrcz/decompress_mrcz公共流程，没有复制正式版本。
        曾测试扩大系数量化为0的区间，但它在mixlay0.f00001和jicf0.f00000上按相同
        PSNR比较时性能均更差，因此已从正式代码删除，原实现备份在
        c_codes/trash/zero_freq_expanding.tpp且不参与构建。
        partition级zero map会记录一个partition内在所有element中都量化为0的系数位置，
        并省略这些位置。在jicf0.f00000的5个field、5个REL error bound上，它不改变
        PSNR，但CR平均只提高约0.107%，最大约0.486%，收益不足以抵消实现和格式复杂度。
        因此也已从正式代码删除，原压缩与解压实现分别备份在
        c_codes/trash/zero_map_compress.tpp和zero_map_decompress.tpp且不参与构建。
        mrcz-experimental方法名暂时保留，作为未来实验的入口；当前行为与mrcz相同。

[x] 13. 整理实验参数及其开关。
        当前只保留if_coefficient_transpose。它是mrcz和mrcz-experimental共用的系数
        无损压缩前布局选项，不再有只属于experimental的开关。
        为保持param_class易于直接修改，暂时继续保留public成员，不额外包装
        experimental_options。命令行不提供实验开关。

[x] 14. 决定暂不增加experimental格式metadata。
        当前没有启用会改变bitstream格式的实验优化，不需要额外metadata。若未来加入并
        需要长期保存或交换experimental文件，再设计版本化metadata。

[x] 15. 把系数无损编解码函数移出原regular文件。
        压缩端函数已移入coefficient_lossless_compress.tpp，解压端函数已移入
        coefficient_lossless_decompress.tpp。当前只包含普通系数流的编解码实现，不再
        依赖已经删除的regular流程文件。

第六阶段：重新整理baseline compressors及后续算法实验
===================================================

[x] 24. 完成正式版与experimental版的对照测试并结束当前实验。
        小数据测试确认两者都满足误差界；jicf0.f00000测试表明zero map收益可以忽略，
        因而已归档并删除该优化。当前mrcz-experimental没有启用实验优化，行为与mrcz
        相同；未来加入新实验功能时再为它补充相应的对照测试。

[ ] 25. 重新检查并统一baseline compressor的名称。
        名称应明确表示数据如何组织、使用哪个API以及预测方式，避免当前SZ3-0、SZ3-1、
        SZ3-HOHS等名称难以直接理解。

[ ] 26. 将当前类似SZ3-0的一维基线重命名并实现为SZ3-1D。
        计划行为：
        - 将每个partition中的数据视为一维数组；
        - 对每个partition分别调用SZ3的一维API；
        - 保存每个partition产生的bitstream长度并依次拼接bitstream；
        - 解压时根据长度信息拆分并分别调用SZ3 API；
        - 统计总bit rate、压缩/解压速度和误差。
        实现前需要将SZ3以独立依赖的形式安装到third_party，并在CMake中提供可靠的
        include和link配置。不要继续依赖无法复现的本地安装路径。

[ ] 27. 增加QoZ baseline。
        QoZ的完整内部实现和参数搜索较复杂，不计划自行复现算法。初步方案是：
        - 将每个partition视为一个4维数组，其中一个维度是element编号，另外三个维度
          是element内部的三个维度；
        - 对每个partition直接调用QoZ官方API；
        - 拼接各partition的bitstream，并记录必要的长度信息；
        - 使用官方推荐配置或明确记录的固定配置，保证实验可复现；
        - 对比rate-distortion、压缩速度、解压速度和内存开销。
        实现前需要调查QoZ的官方版本、构建方法、API、许可证和4维数据支持方式。

[ ] 28. 评估是否需要增加SZ3-4D baseline。
        方案与QoZ-4D一致：把每个partition看作[element, dim0, dim1, dim2]四维数据，
        直接调用SZ3的4维API。
        是否实施取决于：
        - 它与SZ3-1D、逐element SZ3和QoZ-4D能否形成有意义的对照；
        - 论文中是否需要区分“利用4维局部结构”和“仅展平成1维”的效果；
        - 实验数量和篇幅是否允许。

[ ] 29. 调整并测试SZ3-HOHS的遍历/预测顺序。
        当前顺序模仿SZ3。需要增加至少一种“从element中间向外围扩展”的顺序，并在
        完全相同的误差界、量化和无损编码条件下比较：
        - prediction residual分布；
        - bit rate或compression ratio；
        - PSNR/最大误差；
        - 压缩和解压速度；
        - 不同element尺寸及不同field上的稳定性。
        在修改前先把当前遍历顺序写成明确的索引序列或单元测试，保证新旧顺序可复现。

[ ] 30. 评估MRCZ是否需要为每个变换模式使用不同的coefficient error bound。
        当前所有模式共用由coeff_eb_scale得到的系数误差界。可研究：
        - 根据模式对重构误差的放大系数分配error bound；
        - 根据每个模式的平均绝对系数、方差或零频率自适应分配；
        - 在满足最终point-wise error bound的前提下优化总bit rate；
        - 参数是否必须写入metadata，以及额外metadata是否抵消压缩收益；
        - 每个模式一个error bound是否过于复杂，是否应改为少量模式组共享error bound。
        先用离线实验比较统一error bound、分组error bound和逐模式error bound，再决定
        是否进入正式压缩格式。

[ ] 31. 为所有baseline建立统一的实验接口和命名记录。
        每个baseline至少记录：
        - 正式名称和命令行method名称；
        - 输入数据的维度组织方式；
        - partition边界的处理方式；
        - 调用的第三方库版本和API；
        - error-bound语义；
        - bitstream拼接格式；
        - 是否支持float/double及1D/2D/3D element；
        - rate-distortion和速度统计方式。
        在这些定义稳定以后，再修改t1_start_c_code.py中的method_list和论文图例名称。


第七阶段：坐标与文件尾metadata压缩
=====================================

[ ] 32. 增加坐标字段的压缩。
        坐标X、Y、Z的结构和普通物理field不同，不应直接沿用当前的field压缩算法。
        需要先明确坐标压缩的目标和约束：
        - 利用element内GLL点及相邻element之间的几何结构；
        - 确定坐标的error-bound语义，以及是否需要保证公共面上的点严格重合；
        - 评估坐标误差对网格拓扑、element几何和后续数值计算的影响；
        - 为坐标压缩设计独立的bitstream标记和解压路径；
        - 与直接无损保存坐标的方案比较压缩率、速度和几何误差。

[ ] 33. 调查并处理NekRS文件末尾的metadata。
        NekRS开发者提到，这部分数据没有严格的格式约定，官方文档中也没有给出
        完整定义。在实现压缩前需要：
        - 对多个来源和版本的NekRS文件检查正式field数据结束后是否仍有字节；
        - 记录尾部数据的长度、变化情况、生成来源及其是否对原程序有实际用途；
        - 在无法可靠解析时，优先将尾部字节视为opaque blob并无损保存，保证解压后逐字节还原；
        - 比较直接保存、通用无损压缩和不保存三种方案的大小与兼容性；
        - 只有在确认稳定结构后，才考虑为其设计专用压缩方法。
